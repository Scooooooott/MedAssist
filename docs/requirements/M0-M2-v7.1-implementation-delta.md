## Confirmed Existing Behavior

The following behavior already aligns with v7.1 and should be preserved:

- `JdbcLexicalSearchRepository` queries PostgreSQL full-text vectors built from `chunk.text`; contextual prefixes are not queried by the lexical channel.
- `GrpcRerankClient` sends `RetrievedChunk.text()` to the reranker. The retrieved chunk model currently represents original chunk text, so the contextual prefix is not deliberately appended.
- `SpringAiAnswerGenerator` builds evidence from `RetrievedChunk.text()`, and `CitationValidator` validates `quotedSpan` against the same text.
- Context prefixes remain separately stored and are combined with original text only through the embedding text policy; lexical, rerank, final-context, LLM, citation, and display consumers use original text.
- `SearchResponse` already contains `degraded` and `degradation_reasons`; lexical-channel and rerank failures already produce explicit reasons in the retrieval layer.
- The frontend parses named SSE events and rejects malformed or incomplete streams instead of treating them as successful answers.

These observations establish a good baseline, but they do not replace the new explicit regression tests required by v7.1.

## M0 Impact

### No immediate M0 implementation rewrite

M0 remains accepted as the project foundation. The v7.1 additions do not require rebuilding the Maven/Python/frontend skeleton or changing existing service boundaries.

### Contract work to perform before later milestones

The following changes must follow M0's contract-first rule when their owning milestones begin:

1. Extend the user-visible degradation contract from the current boolean plus string list to a versioned structure containing `code`, `affected_stage`, `fallback_mode`, and a safe `reason`. This is owned by M5.3, not an immediate M0 retrofit.
2. Define M5.12 generation-session HTTP contracts before implementation: create, status, event subscription/resume, cancel, terminal events, event IDs, idempotency, and RFC 9457 errors.
3. Add policy resource/action identifiers for trajectory projections and generation-session `create`, `resume`, and `cancel` operations before M4/M5 implementation.
4. Preserve additive compatibility for current M1/M2 clients. Existing `degraded` and `degradation_reasons` fields should not be removed in the first contract revision.

## M1 Impact

### Current stream is a baseline, not resumable streaming

The current browser client uses `fetch` to POST `/api/answer/stream`. The retrieval controller creates an `SseEmitter` and disposes the generation subscription when the connection completes or times out. There are no stable event IDs, generation resource, Redis Stream, ownership checks, replay cursor, or terminal-event replay.

This remains acceptable for M1.10/M1.11. It must not be described as resumable. M5.12 will replace it through an additive migration:

1. Keep the current endpoint during the transition.
2. Add an authenticated, idempotent generation-session creation endpoint.
3. Add authenticated GET/fetch-SSE resume using a stable event cursor.
4. Migrate the frontend to the session state machine.
5. Remove the legacy endpoint only after compatibility tests and an explicit deprecation window.

### Frontend data preservation

The M1 frontend should continue preserving citation source ranges, retrieval metadata, degradation reasons, and stable result identities even when not all v7.1 views are displayed yet. This avoids reparsing answer text or inventing client-only identifiers in M6.5.

The source-document split view, rank-delta visualization, curated trajectory timeline, and disconnect recovery are M6.5/M5.12 work. They are not M1 reopen items.
